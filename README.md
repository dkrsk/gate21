# gate21

Брокер аутентификации для сервисов School 21.

## Назначение

Пользователь проходит аутентификацию на шлюзе логином и паролем School 21;
подключённый сервис получает `access_token` и `refresh_token` без контакта
кода сервиса с паролем. Пароль передаётся в Keycloak транзитом (pass-through),
не хранится и не пишется в логи.

## Возможности

- **Web-поток** — для сервисов с публичным адресом: редирект пользователя на
  шлюз, одноразовый `code` на callback, обмен на токены с бэкенда сервиса.
- **Device-поток** — для ботов без белого IP: клиент запрашивает сессию,
  пользователь открывает ссылку входа, токены забираются поллингом.
- Токены — оригинальные JWT Keycloak; обновление токенов выполняется сервисом
  напрямую у Keycloak.
- Одноразовые коды с коротким TTL (память), constant-time сравнение секретов,
  rate limit по IP, подписанные HttpOnly-куки, анти-open-redirect.

## Предпосылки

OAuth code-flow в Keycloak School 21 закрыт для сторонних доменов, а device-flow
отключён. gate21 реализует оба потока поверх password-гранта и изолирует пароль
от кода подключаемых сервисов.

## Безопасность

Тезисы проверяемы по исходному коду (`src/app/`):

- **Пароль не читается.** Тело `POST /api/login` считывается байтами
  (`src/app/broker/broker.go:218`) и передаётся в Keycloak без разбора и
  пересборки (`src/app/proxy/keycloak.go:45-51`). Входящий запрос не
  десериализуется — полей login/password в коде gate21 не существует.
- **Пароль не хранится.** В `src/app/` нет записи на диск, внешних хранилищ
  и БД. Все состояния — одноразовые коды, device-сессии, выданные токены —
  живут в памяти процесса и удаляются по истечении TTL (`code` — 120 с,
  device-сессия — 5 мин); после выдачи токены не персистятся.
- **Пароль не логируется.** Логи `api/login` содержат только класс ошибки и
  статус-код upstream (`src/app/broker/broker.go:230-251`); тела запросов и
  ответов не логируются.
- **Сопутствующие меры.** Flow-кука подписана HMAC-SHA256
  (`src/app/broker/flow.go:119`), HttpOnly, Secure. Маршруты логина закрыты
  rate limit по IP; секреты клиентов сверяются constant-time; `code`
  одноразовый; редирект проверяется против реестра (анти-open-redirect).

Клиентскому сервису пароль пользователя никогда не передаётся: кредами
распоряжается только login-форма gate21. Обновление токенов (refresh) сервис
выполняет напрямую у Keycloak, без повторного ввода пароля.
